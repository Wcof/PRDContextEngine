# PMSkill 质量看板 PRD

## 概述

**我们要做什么？**

给 PMSkill 项目做一个质量看板 Dashboard。打开一个 HTML 页面就能看到所有 13 个 skill 的质量评分卡——哪个 skill 质量最差、短板在哪里、和历史数据比是进步了还是倒退了——一眼看完。

**为什么现在做？**

PMSkill 项目现在有 13+ 个 SKILL.md，PM 只能靠肉眼逐个读文件来评估质量。darwin-skill 虽然能自动评分，但结果落在 TSV 文件中，不够直观。没有一个"一站式的可视化窗口"让 PM 快速掌握全局。

> **为什么**：看板的本质是把隐性的质量信息转为显性的可视化信息，让 PM 把精力花在"怎么优化"上而不是"哪些需要优化"上。

**谁会从中受益？**

- 日常使用 PMSkill 的 PM：快速知道 skill 质量
- 准备用 darwin-skill 优化的人：一眼看出最有优化空间的 skill
- 优化后的确认：分数有没有真的涨了？

## 用户故事

🎯 **US-1 全局总览**
> 作为 PM，我想一打开看板就看到所有 skill 的评分卡，这样我就能马上了解整体质量水平。

🎯 **US-2 最弱最先**
> 作为 PM，我想默认就看到最弱的 skill 排在最前面，这样我不用在 13 个 skill 里翻找最差的。

> **为什么**：PM 的时间是最稀缺的资源。默认排序应该优先展示问题，而不是中性列表。

🎯 **US-3 短板诊断**
> 作为 PM，我想在每个 skill 卡片上直接看到"这个 skill 最差的 3 个维度"，这样我就知道改哪里。

🎯 **US-4 Bucket 分类**
> 作为 PM，我想按 bucket（setup/discovery/delivery/visualization）分组看 skill，这样我就能评估某个产品区域的整体质量。

🎯 **US-5 分数趋势**
> 作为 PM，如果某个 skill 有多次评分历史，我想看到分数涨跌趋势，这样我就能知道自己做的优化是否真的有效。

## 实施规则

| 规则 | 内容 | 为什么这么定 |
|------|------|------------|
| 数据源 | 从 `results.tsv` 读取 | darwin-skill 已经在此写入数据，避免双源不一致 |
| 评分维度 | darwin-skill 的 9 维 rubric（d1-d9）| 已经过实证验证，一致性最高 |
| 展示形态 | 单 HTML 文件，无服务端 | 嵌入 git 仓库，任何人直接打开即可看 |
| 默认排序 | 分数升序（最弱在前）| PM 最关心的永远是最弱的 skill |
| 更新方式 | 手动刷新 = 重新打开 HTML | 无服务端意味着没有"自动刷新"概念 |

---

## 数据模型

| 实体 | 关键字段 | 说明 |
|------|---------|------|
| Skill | name, bucket, type, description | 来自 SKILL.md 的 frontmatter |
| Score | total, d1-d9, eval_mode, timestamp | 来自 results.tsv 的评估结果 |
| Bucket | setup/discovery/delivery/visualization | 在 skills/ 目录级别定义 |

---

## 验收标准

**US-1 评分卡展示通过条件：**
1. 打开 `dashboard.html` → 看到 13 张评分卡
2. 每张卡片有 skill 名称、总分、bucket 标签、user/model 标记
3. 若 results.tsv 为空 → 显示引导文字，不会崩溃

**US-2 排序通过条件：**
1. 默认排序按总分升序
2. 分数最低的 skill 在列表最顶部

**US-3 短板分析通过条件：**
1. 每张卡片显示该 skill 得分最低的 3 个维度
2. 维度显示实际得分/权重（如 d3: 5/12）

## 风险项

| 风险 | 标记 | 影响分析 |
|------|------|---------|
| results.tsv 格式不稳定 | [待确认] | 看板依赖该格式解析，格式变化会导致看板崩 |
| PM 是否需要趋势图 | [假设] 7/10 | 当前 MVP 不做趋势图，上线后看需求反馈 |

---

## 超出范围

| 排除项 | 理由 |
|--------|------|
| 服务端部署 | 静态 HTML 足够仓库内直接打开 |
| 自动定时扫描 | 依赖 darwin-skill 的评估时间表 |
| 用户登录/权限 | 单用户场景，无需鉴权 |
