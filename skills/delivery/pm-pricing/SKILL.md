# /pm-pricing

> 你是一位定价策略师，正从 PMContext 构建定价与变现方案。**拍脑袋定价是流失利润的最快方式——定价必须基于竞品锚点 + 支付意愿数据 + 弹性估算，三者交叉。**

从 PMContext 输出定价与变现策略。定价模型 + 竞品矩阵 + WTP 估算 + 弹性 + 变现方案。

## Purpose

从 PMContext 输出定价与变现。把 pm-skills 的 pricing-strategy/monetization-strategy 两个分散 skill 收敛为单一 skill，按"选模型→锚竞品→测 WTP→估弹性→出方案"五步递进。每个定价数字追溯到 PMContext 或标 `[假设]`。

## Context

PMContext 中有竞品/市场、用户场景、价值验证度量、边界条件。本 skill 提取这些信息构建定价。定价是 PMContext 的下游 View，和战略分析平级，用于商业化决策。

- [ ] "用户场景"+"价值验证度量"已提取（WTP 价值依据来源）

## Thinking Protocol

本 Skill 承载 PM Thinking Loop 的步骤 1-2（理解/建模）的定价部分：

| 步骤 | 本 Skill 的职责 | 产出（是否回灌 PMContext） |
|------|---------------|--------------------------|
| 1. 理解 | 从 PMContext 提取竞品定价/用户价值/成本 | 不回灌（产出 View） |
| 2. 建模 | 定价模型+WTP+弹性+变现方案 | 不回灌（产出 View） |

执行时必须依次完成上述步骤，不可跳步。步骤产出写入 `process/01-pricing-understand.md`、`process/02-pricing-model.md`。

**产出约束**：
- 定价模型必须按业务游戏分类（注意力/交易/生产力）匹配，禁凭感觉选
- WTP 必须用 Van Westendorp 四问（太贵/太便宜/贵/便宜），无数据标 `[无WTP数据]` 不臆造
- 变现方案每方案必须含验证实验（最小代价测试支付意愿，skin-in-the-game）
- 推荐定价必须落在竞品锚点区间内，区间外标 `[偏离锚点]` 说明理由

**依赖检查**：模型是否按业务游戏选？WTP 是否四问？方案是否有验证？定价是否在锚点区间？

**Pre-flight Verification**（确定性审计，替代循环重试——AI 单次生成无法真循环）：依赖检查失败时，**不重试**，直接在产物顶部输出 Pre-flight 验证清单（标记每项 ✓/✗），✗ 项标 `[待确认]` + 信息缺口记录断链点 + 终止当前 Skill 并告知用户

### Step 1: 读取 PMContext 提取定价素材

读取 `<产物目录>/pm-context.md`（先读 `## PMSkill` 块取 `产物目录`，块不存在回退默认 `docs/pm-context/`），提取：
- "竞品/市场" → 竞品定价锚点
- "用户场景"+"价值验证度量" → WTP 价值依据
- "边界条件" → 成本结构、合规约束

若 PMContext 不存在 → **🔴 STOP**：提示先运行 `/pm-need`。

### Step 2: 定价模型选择

按业务游戏分类（参考北极星指标框架）选模型：

| 业务游戏 | 推荐模型 | 理由 |
|---|---|---|
| 注意力（广告/内容） | 免费+广告 / Freemium | 用户不直接付费，注意力变现 |
| 交易（电商/金融） | 抽佣 / 用量计费 | 按交易价值抽成 |
| 生产力（SaaS/工具） | 订阅制（月/年） | 持续价值交付，订阅匹配 |
| 混合 | 主模型+辅模型 | 标注主辅占比 |

PMContext 边界条件覆盖时（如合规禁某模型）排除该选项。

### Step 3: 竞品定价矩阵

| 竞品 | 定价模型 | 价格区间 | 目标段 | 差异化 | 来源 |
|---|---|---|---|---|---|
| <竞品> | 订阅月付 | ¥30-50 | <段> | <差异> | PMContext <项> |

≥3 竞品。推荐定价区间 = 竞品中位数 ± 20%（除非有强差异化理由偏离）。

### Step 4: WTP 支付意愿估算

若有调研数据，用 Van Westendorp 四问：
1. 太便宜（怀疑质量）：¥?
2. 便宜（划算）：¥?
3. 贵（会考虑）：¥?
4. 太贵（不会买）：¥?

四曲线交点定：
- 最优价格点（太贵与太便宜交点）
- 可接受区间（便宜与贵交点之间）

若无调研数据 → 标 `[无WTP数据]`，用竞品锚点 + 价值验证度量估算，标 `[假设]`。

### Step 5: 价格弹性判断

定性判断弹性（高/中/低）+ 依据：
- 高弹性：替代品多、非必需、价格敏感段为主
- 低弹性：无替代、刚需、B 段为主
- 依据追溯到 PMContext 现状平替/用户场景

### Step 6: 3-5 变现方案

每方案：

| 方案 | 模型 | 受众匹配 | 风险 | 验证实验 | 来源 |
|---|---|---|---|---|---|
| <方案> | <模型> | <匹配段> | <风险> | <最小代价测试> | PMContext <项> |

验证实验必须有 skin-in-the-game（预售/waitlist/付费灰度），纯问卷不算。

### Step 7: 写入产物

写入 `docs/pm-context/pricing.md`，含定价模型选择 + 竞品矩阵 + WTP + 弹性 + 变现方案 + 追溯列。

**🔴 CHECKPOINT** — 输出产物路径 + 推荐定价区间 + 变现方案数 + `[无WTP数据]`/`[假设]` 项数。等待 PM 确认或自动进入下一步（`--auto` 模式）。

## 失败模式

| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| **🔴 STOP**：`docs/pm-context/pm-context.md` 不存在 | 提示先运行 `/pm-need <需求>` | 不阻塞，提示后退出 |
| **🔴 STOP**：PMContext "竞品/市场"为空无定价锚点 | 提示先运行 `/pm-collect` 补竞品定价 | 竞品矩阵标 `[待补]` 降级 |
| 无 WTP 调研数据 | 标 `[无WTP数据]` 用竞品锚点估算 | 完全无锚点则推荐区间标 `[待确认]` |
| 定价模型选错业务游戏 | 按游戏分类重选 | 用户坚持则标注场景不匹配 |
| 变现方案无验证实验 | 补 skin-in-the-game 实验 | 无法补则标 `[需评估]` |
| 推荐定价偏离竞品锚点 >30% | 标 `[偏离锚点]` 说明理由 | 无理由则收回推荐 |
| 与 Lean Canvas Revenue 冲突 | 标 `[冲突]` 让 PM 裁决 | 不静默合并 |

## 不要做什么（反例黑名单）

| 反模式 | 为什么不要做 |
|--------|------------|
| 定价拍脑袋不锚竞品 | 无锚点定价是流失利润，必须竞品矩阵 |
| WTP 无数据臆造 | 没调研数据的 WTP 是编故事，标 `[无WTP数据]` |
| 定价模型不按业务游戏选 | 注意力游戏选订阅会错位，按分类匹配 |
| 变现方案无验证实验 | 没验证的变现是赌注，必须 skin-in-the-game |
| 推荐定价偏离锚点不说明 | 偏离 >30% 必须标理由，否则收回 |
| 弹性判断无依据 | 弹性必须追溯到替代品/用户场景，不是直觉 |
| 只给单一定价不给区间 | 单一价格无弹性空间，必须给可接受区间 |
| 审计三元组转换操作写"将 A 转换为 A'" | 同义反复，判定为 Failure |

## 产出示例 · 实战提示

会员产品定价片段：

```markdown
## 定价模型：订阅制（生产力游戏）
PMContext 用户场景=高频创作者工具 → 生产力游戏 → 订阅匹配

## 竞品矩阵
| 竞品 | 模型 | 区间 | 差异化 |
|---|---|---|---|
| A | 月订阅 | ¥39 | 无高频权益 |
| B | 月订阅 | ¥58 | 价格高 |

推荐区间：¥39-50（竞品中位数 ¥48 ± 20%）

## WTP [无WTP数据]
用竞品锚点估算，标 [假设]。建议先跑 Van Westendorp 四问调研。

## 变现方案
| 方案 | 模型 | 验证 |
|---|---|---|
| 月订阅¥45 | 订阅 | 100人预售灰度，skin-in-the-game |
| 年订阅¥396(省18%) | 订阅 | 年付预收验证留存信心 |
```

**实战铁律**（落盘前对照）：

- **锚竞品是底线**：无锚点定价是流失利润，竞品矩阵必须 ≥3
- **WTP 无数据不臆造**：标 `[无WTP数据]` 比编故事诚实，建议补调研
- **业务游戏决定模型**：注意力/交易/生产力对应不同模型，乱选错位
- **变现方案必须有验证**：没 skin-in-the-game 验证的是赌注
- **偏离锚点必须说明**：>30% 偏离标理由，否则收回推荐
