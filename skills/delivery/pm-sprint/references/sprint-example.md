# 迭代规划完整示例

## 场景

会员产品 2 周迭代规划，pm-stories 产物有 12 个故事，pm-prioritize 已排序。

## 容量估算

```
团队容量 = 5 人 × 80% 可用 × 40 点/迭代历史速率 × (1-20% buffer) = 128 点
```

| 项 | 值 | 来源 |
|----|----|----|
| 人数 | 5 | PMContext 全局约束 |
| 可用% | 80%（扣 PTO/会议/on-call） | 用户提供 |
| 历史速率 | 40 点/迭代（近 3 迭代均值） | 历史数据 |
| buffer | 20% | 固定规则 |
| **可用容量** | **128 点** | 计算 |

## 故事选取（共 122 点）

| 故事 | 优先级 | 点数 | DoR | 依赖 | 选取 |
|------|--------|------|-----|------|------|
| 一键续费 | P0 | 8 | ✅ | 无 | ✅ |
| 续费提醒 | P0 | 13 | ✅ | 内部:通知模块 | ✅ |
| 会员等级展示 | P1 | 5 | ✅ | 无 | ✅ |
| 自动续费开关 | P0 | 13 | 🟡 验收不清 | 内部:一键续费 | 🟡 需 refinement |
| 续费数据分析 | P2 | 8 | ✅ | 外部:BI 平台 | ✅（标外部依赖） |
| ... | | | | | |
| **累计** | | **122 点** | | | ≤ 128 容量 |

## 依赖映射

| 故事 | 依赖类型 | 依赖对象 | Owner | 风险 |
|------|---------|---------|-------|------|
| 续费提醒 | 内部 | 通知模块 | 团队内 | 低 |
| 续费数据分析 | 外部 | BI 平台 | 数据团队 | 中（需提前对齐） |

关键路径：一键续费 → 续费提醒 → 续费数据分析

## 风险矩阵

| 风险 | 影响 | 缓解 |
|------|------|------|
| 自动续费开关验收不清 | 范围蔓延 | 迭代第 1 天 refine |
| BI 平台外部依赖 | 阻塞 | 迭代前对齐 + 备选：手动导出 |
| 仅李四懂支付逻辑 | 单点故障 | 结对王五知识共享 |

## Sprint Goal

让到期会员在 3 次点击内完成续费（对应 PMContext 用户场景"续费流程太麻烦"）

## 审计三元组

`<依据集: [pm-stories 产物 12 故事, pm-prioritize 排序, PMContext 全局约束"5人团队"]> → [工具: /pm-sprint, 规则: 容量公式+DoR] → [转换: 按 PMContext 度量口径对齐故事点数与容量，多对多实体映射：故事→容量→迭代] → <产出: 128 点容量+122 点选取+Sprint Goal>`
