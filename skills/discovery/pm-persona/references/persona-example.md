# 用户画像完整示例

## 场景

会员产品从 PMContext 用户场景与反馈数据构建 3 个 persona。

## 3 个 Persona

### Persona 1: 独立创作者小林
- Demographics: 28 岁/一二线/自由职业 ← PMContext 用户场景
- Behaviors: 日更/工具切换频繁/社群决策/单人 ← PMContext 用户场景
- JTBD:
  - 功能性: 让创作产能稳定输出
  - 情感性: 降低断更焦虑
  - 社会性: 被同行认可专业
- 未满足需求: 当前用 Excel+日历手动排期，断更无预警 ← PMContext 现状平替
- 代表性引言: "我每天醒来第一件事是担心今天发什么" ← 来源: review_001
- 反对意见:
  - "我用 Excel 习惯了" ← PMContext 边界条件"迁移成本"
  - "月费 ¥30 对自由职业有压力" ← PMContext 边界条件"价格敏感"

### Persona 2: 团队主理人老王
- Demographics: 35 岁/二三线/小工作室主理人 ← PMContext 用户场景
- Behaviors: 管理小团队/协作需求/决策者+使用者 ← PMContext 用户场景
- JTBD:
  - 功能性: 让团队内容产能可追踪
  - 情感性: 降低交付不确定性焦虑
  - 社会性: 被客户认为专业可靠
- 未满足需求: 当前用飞书文档+微信群，进度散落难汇总 ← PMContext 现状平替
- 代表性引言: "客户问进度我要翻 3 个群找答案" ← 来源: interview_002
- 反对意见:
  - "飞书已经够用了" ← PMContext 边界条件"替代品成熟"
  - "团队学习成本高" ← PMContext 边界条件"迁移成本"

### Persona 3: 企业内容总监李姐
- Demographics: 42 岁/一线/企业内容部门负责人 ← PMContext 用户场景
- Behaviors: 管理大盘/看数据报表/审批者/批量采购 ← PMContext 用户场景
- JTBD:
  - 功能性: 让部门内容产出可度量可汇报
  - 情感性: 降低向上汇报的被动感
  - 社会性: 在管理层展现数字化能力
- 未满足需求: 当前无统一看板，月底手动汇总 ← PMContext 现状平替
- 代表性引言: "月底汇报我要花 2 天手动汇总数据" ← 来源: review_007
- 反对意见:
  - "企业版价格需走采购审批" ← PMContext 边界条件"采购流程"
  - "数据安全合规要评估" ← PMContext 边界条件"合规"

## 互斥校验

| persona | 核心行为 | JTBD 核心 | 与其他重叠? |
|---------|---------|----------|-----------|
| 小林 | 独立创作 | 稳定输出 | 无 |
| 老王 | 团队协作 | 团队对齐 | 无 |
| 李姐 | 大盘管理 | 可度量汇报 | 无 |

互斥性 ✅（重叠 <20%）

## 与 pm-interview 联动

每 persona 设计定向访谈：
- 小林: 断更焦虑的触发场景 + 当前平替具体流程
- 老王: 团队协作的最痛摩擦点 + 替代品切换成本
- 李姐: 向上汇报的数据需求 + 采购流程关键卡点

## 与 pm-market 用户分层互补

| pm-market 分层 | 对应 persona | 关系 |
|---------------|-------------|------|
| 层 1: 独立创作者 | 小林 | 群体→个体 |
| 层 2: 小团队主理 | 老王 | 群体→个体 |
| 层 3: 企业管理者 | 李姐 | 群体→个体 |

分层看群体差异（规模/占比），persona 看个体立体（引言/反对意见）。
